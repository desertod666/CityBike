# CityBike / Kolumbus Bysykkel diagnostics

Проект читает CAN велосипеда через ESP32-C3 и эмулирует сервисный BLE-пульт.
Актуальная прошивка находится только в `reader/`. Сайт находится в `web/`,
сервер приёма записей и удалённого управления — в `server/`.

## Что работает и что ещё проверяется

- Пассивный приём: 250 кбит/с, профиль TRIPLE. Полные USB-записи сохраняются
  отдельно от ограниченного экранного буфера и мониторинга.
- Отображение данных контроллера, батареи и текущих предупреждений Bafang.
  По ячейкам показываются только реально полученные ответы; отсутствие
  ответа не означает неисправность батареи. История ошибок PCB отдельно не прочитана.
- Сервисный BLE-пульт: включение/выключение трансляции, кнопки без фиксации,
  подтверждение Power off, ограниченные сроки удержания и запись CAN вокруг действий.
  Исполнитель пульта сейчас требует USB и открытой страницы на ПК.
- Передача запросов батарее на велосипедной CAN пока не подтверждена.
  Изолированный тест проходит без нагрузки, но проверка через трансивер
  с 120 Ом пока не проходит. Причина не установлена. Версия 0.6.7 добавляет
  независимую проверку уровней GPIO без драйвера CAN и сохраняет ошибку
  до остановки драйвера. Версия 0.6.8 явно настраивает вход GPIO5 и добавляет
  отдельное фиксированное удержание для мультиметра при отсоединённой CAN.
  Эти проверки не доказывают неисправность микросхемы.
- Отдельный стандартный активный опрос ячеек 6400–6404 ещё не реализован.
  Параметры батарей, прошивки контроллеров и произвольный replay не входят
  в подтверждённые возможности прибора.

## Сборка актуальной прошивки

Основной путь — `.github/workflows/reader-ci.yml` на GitHub. Он проверяет
фиксированные версии инструментов, исходники, 13 наборов проверок прошивки,
совпадение сайта и встроенных файлов, размер раздела и фактические ассеты ELF.
Артефакты находятся в `reader/ci-artifacts/`. CI не обращается к велосипеду.

Для локальной сборки с установленными зависимостями:

```sh
python scripts/sync_reader_web.py
python -m platformio run -d reader -e esp32c3
python reader/scripts/verify_ci.py
```

На Windows `build.bat` собирает именно `reader/` и кладёт результат в
`reader/artifacts/`. `flash.bat COM9` требует явно выбранный порт.
Корневые `src/`, конфигурация и старые PC-инструменты сохранены для истории;
сборка старой корневой прошивки заблокирована. `build_pc.bat` собирает только
прежнюю настольную программу и не упаковывает её со старой прошивкой.

После изменения `web/` выполните `python scripts/sync_reader_web.py`.
Проверка `--check` ничего не меняет и выявляет расхождение с `reader/web/`.
Изменение файлов исходников портала не обновляет уже установленную ESP.

## Проверки сайта и сервера

```sh
python scripts/test_app_regressions.py
python scripts/test_app_regressions.py --browser
```

Проверки используют временное хранилище, искусственные команды и локальный
HTTP-сервер. Для второго варианта нужен Playwright 1.56.1 и Chromium.
Workflow `app-ci.yml` устанавливает их на GitHub и проверяет работу обновления
страницы в настоящем браузере. Личные CAN-записи и ключи сервера ему не нужны.

## Подключение

| ESP32-C3 | CAN-трансивер SN65HVD230, 3,3 В |
|---|---|
| 3V3 | VCC / 3V3 |
| GND | GND |
| GPIO4 | CTX / TXD |
| GPIO5 | CRX / RXD |

В пассивном режиме GPIO4 удерживает рецессивный уровень, а TWAI TX направлен
на неподключённый GPIO10. Разрешённые диагностические операции временно
переключают маршрутизацию и затем восстанавливают её. Обычное чтение CAN
не включает такую передачу. Резистор 120 Ом устанавливают на конце линии;
необходимость дополнительного резистора зависит от имеющегося согласования.

Портал ESP доступен в её Wi-Fi-сети по `http://192.168.4.1`. Для USB-сайта
нужен Chrome/Edge с Web Serial. Автоматическое обновление ждёт завершения
записей, прошивок и управления пультом; один пассивный просмотр может быть
кратко остановлен и восстановлен после обновления на той же ESP.
